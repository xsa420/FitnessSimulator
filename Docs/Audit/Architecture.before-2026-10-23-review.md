# [FRAME] 工程边界与接入约定

[COMPUTED｜HIGH] 当前工程实现了工程基础与训练资源原型，正式事件调度、训练数值、剧情、经济、结局 UI 尚未实现。下列架构依据本次对话已确认并同步到[项目文档](https://app.notion.com/p/2bc3e8eb2dfd80bcb359f603fc989244)的规则更新；原型接口不是已冻结的正式数据协议。

## [FRAME] 正式实现基线

[FRAME｜已确认] 时间锚点及其顺序可配置增加，包括三餐锚点。普通事件树的节点、入口条件和后续分支固定配置，入口通过随机、选择等方式进入预定分支，且必须配置默认事件兜底。每个子事件结算后，以最新玩家数据判断配置好的后继；不重新抽取整个锚点的入口池。正常没有后继时结束当前树；错误的必需引用或不可用的默认入口是配置错误。

[FRAME｜已确认] 剧情、小游戏、训练结算、用餐、演出、结局演出、结束当前动作、前进到下一时间锚点均通过事件接口执行。训练是复合事件：进入时读取计划，生成“剧情 → 小游戏 → 训练结算 → 固定后续事件组 → 后续组/动作”的运行时树，交给同一个执行器。固定事件组可以插入突发链。

[FRAME｜已确认] 结束当前动作事件仅配置在训练结算后，跳过该动作剩余组；它不表示只结束本组。通用的前进到下一时间锚点事件终止当前锚点剩余事件，包括未完成训练。用餐锚点可被消耗，消耗后跳过该次用餐。

[FRAME｜职责] 执行器拥有事件生命周期、流程位置及提交协调权；事件处理器返回结果与控制意图。训练模块生成树并解释训练语义，数值模块计算数据变更，存档模块持久化提交结果和恢复快照，表现模块等待演出/交互真正结束才回报完成。界面、小游戏和演出不能各自另建一套全局结算或保存流程。

[FRAME｜独立服务] 玩家状态与数值计算、计划编辑、经济/背包/关系数据、配置加载与校验、存储与版本迁移、历史记录与笔记、输入与界面表现、构建与诊断是独立模块。它们由事件调用或支持事件执行，但不必把每个函数或每次界面操作都变成事件节点。

## [FRAME] 目录职责

| 目录 | 职责 |
|---|---|

| Runtime/Persistence | 本机 JSON 写入/读取；当前局与结局历史的数据外壳 |

## [FRAME] 训练接入

[COMPUTED｜HIGH] `ITrainingMinigame.Begin` 接受一组请求并回传结果；包含动作、目标次数、等级/重量、训练组类型，以及实际次数、表现载荷、游戏内用时和连续力量组统计。具体计分、难度与单位留给已确认的动作玩法实现。

[FRAME] 后续训练模块负责容量组自动执行资格、历史表现复用、组间休息以及请求/结果语义；数值模块负责临时疲劳等数值计算，统一事件提交协调结果落地。展示层只播放模型和动画，不直接改变角色数值。候选资源中的肌群标签用于展示检索，未替代 B 模块的最终数值字段。

[FRAME] 接入一个新动作：创建模型预制体和动画 → 创建 `ExercisePresentation` → 填入目录 → 实现 `ITrainingMinigame` → 在编排层连接结果与事件结算。小游戏要能停在指定动作阶段；正式实现建议使用骨骼动画状态机及明确的次数/阶段事件。

## [FRAME] 存储与事件边界

[COMPUTED｜HIGH] `LocalJsonStore` 用同目录临时文件写入、刷盘，再替换旧文件。当前局和历史使用不同槽名；路径遍历被拒绝。实验场只写 `DevelopmentProbe/probe.json`，不会伪造一局正式游戏。

[FRAME｜已确认] 每个已完成子事件都提交、保存并检查结局；包括小游戏、训练结算、用餐、控制与日结子事件。事件组、当前动作及训练容器收尾不额外检查。结局演出期间的已完成子事件仍保存，但不嵌套检查另一个结局。提交需要一致保存数据、事件位置、完成标记与随机状态，恢复时不得重复累计已结算结果。

[FRAME｜已确认] 普通未完成事件从该事件开头恢复；演出未结束即事件未完成。训练动作未完成时退出再恢复，回退整个当前动作至动作开始快照，包含该动作内已经完成的组；之前完成的动作保留。每子事件保存与动作级退出回退同时存在，不能混成一个检查点。

[FRAME｜已确认] 触发结局后选择续玩，保留触发时的数据并从后续事件继续，不回退当前动作。当前局存档只有一个槽，历史结局快照独立保存。计划编辑可保存计划，但不能顺带提交正在执行的未完成事件。

[FRAME｜待决] 结局续玩后仍在同一动作、随后再次退出时的回退基线，由 P5 主责，P2/P1 协同，对接策划 F/A/E；计划编辑与动作回退的字段范围由 P5/P2 对接 F/A。开发前确定这些协议，不在原型存档外壳中猜测实现。默认入口次数与无限天数等边界由 P1/P7 对接 E。

## [FRAME] 程序工作包与进度入口

[FRAME] A–F 是策划职责；P1–P7 是程序职责，不能按策划分组直接复制代码边界。下列为分工设计，尚未启动正式玩法实现，也未创建或派发程序 agent。

| 程序责任包 | 实现职责 | 主要策划接口 |
|---|---|---|
| [FRAME] P1 流程 | 会话、锚点、入口、统一执行器、控制事件、提交与结局调度 | E；涉及训练/经济/结局时 A/C/F |
| [FRAME] P2 训练与小游戏 | 计划、动态树、训练上下文、休息、自动执行、小游戏计时与结果 | A；B/E 协同 |
| [FRAME] P3 状态与数值 | 状态字段、纯数值计算、效果协议 | B；C/D/E 协同 |
| [FRAME] P4 生活与经济 | 饮食、交易、背包、关系服务及事件接入 | C/D；B/E 协同 |
| [FRAME] P5 存档与记录 | 子事件提交持久化、动作快照、恢复、版本、历史结局与笔记 | F；A/E 及数据所有者协同 |
| [FRAME] P6 界面与表现 | UI、输入、演出、模型动画、教学呈现 | F；A/E 协同 |
| [FRAME] P7 工程与配置 | 配置工具与校验、无界面验证、集成与构建 | 对应配置的 A–F 策划 |

[FRAME] 主架构责任是协议、依赖边界、工作包、集成验收与进度把控；玩法细节由对应程序 agent 与策划沟通。推进顺序：接口冻结 → 固定事件树闭环 → 单动作训练闭环 → 完整日循环 → 内容与平台验收。当前只完成架构文档与研发准备，不能把现有四个原型测试当作正式事件系统验收。

## [FRAME] 视觉资产边界

[FRAME｜已确认] 2026-10-22 用户确认资源调研／工程演示采用卧推、哑铃弯举、高位下拉、绳索下压、深蹲、臀推、肩推、侧平举 8 个候选动作，美术方向为风格化卡通 3D。该范围不自动确定正式小游戏操作、评分或数值；具体视觉方案尚未定稿。

[COMPUTED｜HIGH] 当前人物由独立几何部件组成，动画为部件变换曲线；可编辑、可构建，但不是蒙皮 Humanoid 成品。模型没有引用商店素材或在线人物图像，动作曲线为本工程程序生成。

[FRAME] 原型用于核验资产绑定、镜头和构建链路。正式动作需通过肢体比例、关节轨迹、握持接触、器械绳索/配重同步、循环接缝的逐项审查，之后再承担教学展示。采购的人体骨骼动画需重定向，不可直接假定能套用到部件动画原型。

[FRAME] 图形 API：桌面使用模板配置，移动端当前为 OpenGLES3、ARM64、IL2CPP；表现层共用 URP。横屏界面首版为开发工具，不是最终产品 UI。原型文字为英文，正式中文字体与本地化后续接入。

[COMPUTED｜HIGH] 初次 Android 生成工程即使关闭强制网络权限，仍带有 INTERNET 声明。工程增加最终清单合并规则，移除该权限；后续加入联网功能时必须明确调整这项离线约束。
